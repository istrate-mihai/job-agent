JOB-AGENT — COMMAND CHEAT SHEET
Run everything in Git Bash, with Docker Desktop started.
Project folder: ~/projects/job-agent   (C:\Users\Istrate Mihai\projects\job-agent)

WHAT THE APP DOES
  1. Collects job postings: Remotive, Jobicy (remote, Romania/Europe), Endava careers
     (SmartRecruiters), and your Gmail job-alert emails (LinkedIn, eJobs, BestJobs).
  2. Filters them for free (no AI): titles, locations (Brașov / remote / relocation cities),
     age, blocklisted companies, required languages.
  3. Scores each remaining posting 0-100 against your master CV using free AI (Groq/Gemini):
     apply (70+), maybe (50-69), skip (under 50).
  4. Fetches the full job text for alert-email postings and drops closed ones (enrich).
     Shows you a digest. YOU approve or skip each posting.
  5. For approved postings it builds a tailored CV (PDF), a 3-sentence cover note and a
     review file (diff.md). Bullets are always your own text from master-cv.json.
  6. YOU apply manually, then track the application (applied → interview → offer).

------------------------------------------------------------------------------------
DAILY ROUTINE (in this order)
------------------------------------------------------------------------------------
1) Start + collect + fetch descriptions + score + digest (all automatic):
  cd ~/projects/job-agent && npm run db:up && npm run gmail:check && npm run pipeline

   pipeline = ingest → enrich → score → digest
   enrich fetches the full job text for alert-email postings (LinkedIn, eJobs, BestJobs),
   drops closed/expired postings, and queues them for re-scoring with the real text.
   Show skipped postings too:   npm run digest -- --all
   id = the 8 characters in [brackets] in the digest

2) Only if a posting still shows "title-only" (the site blocked the fetch):
  npm run enrich -- --retry                     try again later
  npm run describe -- <id> jobs/<id>.txt        last resort: paste the job text yourself

3) Decide:
  npm run decide -- <id> approve "reason"
  npm run decide -- <id> skip "reason"
   Aim for max ~5 approvals per day.

4) Build tailored CV + cover note:
  npm run tailor                  all approved postings (45 s pause between them)
  npm run tailor -- <id>          one posting (or re-tailor it)
  npm run tailor -- <id> --allow-title-only   force it without a description (not advised)
   Output: output/applications/<date>_<company>_<title>_<id>/
           Istrate_Mihai_Septimius_<Job_Title>_<Company>_CV.pdf
           Istrate_Mihai_Septimius_<Job_Title>_<Company>_Cover_Letter.pdf   (upload this)
           Istrate_Mihai_Septimius_<Job_Title>_<Company>_Cover_Letter.txt   (paste into forms)
           diff.md (review first), tailoring.json
   If Groq hits its rate limit: wait 1 minute and run it again.

5) Review before applying (always):
   - diff.md "✖" rows = requirements you don't prove → prepare an honest answer
   - read the cover letter: correct stack? honest about gaps? no invented claims?
   - open the PDF

6) Apply yourself on the company site / LinkedIn, then record it:
  npm run track -- <id> applied "where/how"

7) Follow up:
  npm run track                   board: what's next per posting, "← follow up" after 7 days
  npm run track -- <id> responded | interview | offer | rejected

8) Stop the database (data is kept):
  docker compose stop db

------------------------------------------------------------------------------------
MAINTENANCE
------------------------------------------------------------------------------------
Check the config and CV data:
  npm run typecheck && npm run validate:cv

Render your base (untailored) CV:
  npm run cv:base                  → output/Mihai_Septimius_Istrate_CV.pdf

Exclude Java-only roles before scoring (saves AI quota):
  add java to titles.exclude in config/search-config.yaml, then npm run refilter

After editing titles / locations / blocklist in config/search-config.yaml:
  npm run refilter                 re-check postings rejected under the old rules

Check which AI models your keys can use:
  npm run llm:models

Diagnose Gmail alerts (shows real sender addresses, ✔ = caught, ✖ = missed):
  npm run gmail:check

Re-authorize Gmail (if you see "invalid_grant"):
  npm run gmail:auth

After a code update with database changes:
  npm run db:generate && npm run db:migrate

Enrichment: LinkedIn is read through its public logged-out job pages (no account used).
  Turn it off with  enrich: { enabled: true, linkedin: false, maxPerRun: 30, delaySeconds: 3 }
  in config/search-config.yaml. "LinkedIn HTTP 999/429" = LinkedIn is throttling; retried next run.

AI errors: 429 = Groq per-minute limit (wait 1 min), 503 = Gemini overloaded (try later),
"fetch failed" on ollama = not installed (ignored).

AI usage so far:
  docker compose exec db psql -U jobagent -d jobagent -c "SELECT model, count(*) AS calls, sum(input_tokens) AS input, sum(output_tokens) AS output FROM llm_usage GROUP BY 1 ORDER BY 2 DESC;"

------------------------------------------------------------------------------------
KEY FILES
------------------------------------------------------------------------------------
  config/search-config.yaml   what to search: sources, titles, locations, thresholds
  data/master-cv.json         your CV facts (the only source of CV content)
  data/photo.jpg              CV photo (set tailoring.photoPath: null for no photo)
  .env                        API keys + database URL (never commit)
  secrets/                    Gmail credentials/token (never commit)
  output/                     generated CVs (gitignored)

GMAIL TIP: don't delete alert emails before running the pipeline. Use a Gmail filter
(From: jobalerts-noreply@linkedin.com OR ejobs.ro OR bestjobs.eu → Skip the Inbox +
label "job-alerts") so they stay out of your inbox but remain searchable.

Add an employer's careers feed (Greenhouse, Lever, SmartRecruiters, Workable, Recruitee, Personio):
  npm run ats:probe -- https://company.com/careers "Company Name"
  paste the printed "✔" line into config/search-config.yaml under the matching source, then npm run ingest
  "uses Workday/Avature/Phenom…" = no public feed: set a LinkedIn alert for that company instead
